# Deploy NiyamSetu on Render

These steps assume you are pushing this repository to GitHub and deploying it as a Render web service.

Official Render references:

- Native Node web services: https://render.com/docs/web-services
- Blueprints: https://render.com/docs/blueprint-spec
- Persistent disks: https://render.com/docs/disks
- Docker services, if you deploy the Dockerfile elsewhere: https://render.com/docs/docker

## Why This Uses Native Node On Render

The repository still includes a Dockerfile, but `render.yaml` uses Render's native Node runtime. This avoids Render Docker registry build-cache failures like `failed to configure registry cache importer ... buildcache: not found`.

## 1. Prepare GitHub

Commit these deployment files:

```text
.node-version
Dockerfile
.dockerignore
docker-compose.yml
render.yaml
.env.example
scripts/healthcheck.js
docs/deployment_render.md
```

Do not commit `.env`, `data/*.db`, `data/*.log`, generated Chrome profile folders, or any real secret values.

## 2. Local Test

npm start
```

Open:

```text
http://127.0.0.1:8765
```

Health endpoint:

```text
http://127.0.0.1:8765/api/health
```

## 3. Render Blueprint Deploy

1. Push the repository to GitHub.
2. In Render, create a new Blueprint from the repository.
3. Render will read `render.yaml`.

`NIYAMSETU_SIGNING_KEY` is generated by the blueprint.

The blueprint configures:

- Native Node runtime using Node 24.
- Build command `npm install --omit=dev`.
- Start command `npm start`.
- Health check path `/api/health`.
- Persistent disk mounted at `/var/data/niyamsetu`.
- `NIYAMSETU_DATA_DIR=/var/data/niyamsetu` so SQLite survives restarts.

## 4. Manual Render Deploy Alternative

If you do not use the blueprint:

- Service type: Web Service.
- Runtime: Node.
- Build command: `npm install --omit=dev`.
- Start command: `npm start`.
- Health check path: `/api/health`.
- Environment variables:

```text
NODE_VERSION=24
NODE_ENV=production
HOST=0.0.0.0
NIYAMSETU_DATA_DIR=/var/data/niyamsetu
Set the session signing key in the Render dashboard, or let the blueprint generate it.`r`n```

Do not set `PORT`; Render provides it.

Add a persistent disk:

```text
Name: niyamsetu-data
Mount path: /var/data/niyamsetu
Size: 1 GB
```

## 5. Free/Ephemeral Option

If you deploy without a persistent disk, the app still runs, but signup users, logs, and audits reset when the service restarts. In that case set:

```text
NIYAMSETU_DATA_DIR=/tmp/niyamsetu
```

## 6. Post-Deploy Check

After Render deploys, open:

```text
https://<your-render-service>.onrender.com/api/health
```

You should see `ok: true`. Then open the service root URL and use Guest Access or Signup.
